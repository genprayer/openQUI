# VS Code для OpenQUI: настройка и устранение ошибок

Основной способ работы — открыть этот репозиторий в Dev Container. Тогда
редактор, компилятор, заголовки Qt и терминал используют одно окружение.
Гайд описывает этот порядок работы; версии зависимостей и параметры сборки
берутся из конфигурации проекта.

## Настроить один раз

1. Установите VS Code и Docker. Docker должен запускаться из вашей обычной
   пользовательской сессии. Проверка в терминале хоста: `docker info`.
2. В VS Code выберите **File: Open Workspace from File** и откройте
   [OpenQUI.code-workspace](../OpenQUI.code-workspace). Рабочей папкой должен
   быть этот проект, а не общий каталог `Projects` и не отдельный `.cpp`.
3. Установите рекомендуемые расширения из
   [.vscode/extensions.json](../.vscode/extensions.json). Для входа в контейнер
   нужно **Dev Containers**; внутри него — **C/C++** и **CMake Tools**.
4. Нажмите `Ctrl+Shift+P`, выполните **Dev Containers: Reopen in Container**.
   При первом открытии Docker собирает окружение из
   [Dockerfile.dev](../packaging/Dockerfile.dev). VS Code устанавливает
   указанные C++ расширения в контейнер.
5. Дождитесь завершения настройки. В левом нижнем углу VS Code должно быть
   подключение к Dev Container. Откройте **новый** встроенный терминал.
6. Если CMake Tools просит выбрать конфигурацию, выполните
   **CMake: Select Configure Preset** и выберите `editor`. Затем выполните
   **CMake: Configure**. Этот же пресет использует автоматическая настройка.

При открытии проекта локально установка расширения C/C++ сама по себе не
устанавливает Qt, компилятор и CMake. Если редактор работает на хосте, а
заголовки находятся только в Docker, ошибки `cannot open source file` ожидаемы.
Здесь они устраняются работой редактора в том же контейнере, где выполняется сборка.
Это стандартный сценарий [VS Code Dev Containers](https://code.visualstudio.com/docs/devcontainers/create-dev-container).

## Убедиться, что окружение выбрано правильно

В новом терминале VS Code выполните:

```sh
pwd
command -v cmake
command -v c++
command -v ninja
pkg-config --modversion Qt6Quick
cmake --list-presets
```

Все инструменты должны находиться, Qt должен выводить свою версию, а список
пресетов — содержать `editor`. Рабочая папка терминала должна совпадать с
`workspaceFolder` в [.devcontainer/devcontainer.json](../.devcontainer/devcontainer.json).
Если терминал открыт в другой папке, вернитесь в корень проекта.

Выполните **OpenQUI: Configure** через **Tasks: Run Task**. После успешной
настройки появится `build/editor/compile_commands.json`. Он содержит реальные
параметры C++ компиляции, включая Qt. CMake Tools передаёт их C/C++ расширению;
контейнерная конфигурация также задаёт путь к этой базе явно.

Не переносите контейнерную базу на хост с заменой только имени проекта.
Пути к компилятору и системным заголовкам тоже принадлежат окружению сборки.
Ручной список `includePath` для каждого Qt-модуля здесь не требуется.
См. [настройку IntelliSense](https://code.visualstudio.com/docs/cpp/configure-intellisense).

## Ежедневная работа

| Действие | Как выполнить |
| --- | --- |
| Собрать проект | `Ctrl+Shift+B`, задача **OpenQUI: Build** |
| Собрать и запустить тесты | **Tasks: Run Task → OpenQUI: Test** |
| Проверить переводы | **Tasks: Run Task → OpenQUI: Translations** |
| Повторно настроить CMake | **Tasks: Run Task → OpenQUI: Configure** |

Задачи определены в [.vscode/tasks.json](../.vscode/tasks.json). Сборка сначала
выполняет настройку CMake; тесты сначала выполняют сборку. Ошибки GCC из задачи
сборки попадают в Problems через стандартный обработчик `$gcc`.
Конкретные версии инструментов и случайное имя Docker-контейнера в командах
задач не используются. [Документация задач VS Code](https://code.visualstudio.com/docs/debugtest/tasks).

Если предпочитаете терминал, используйте те же пресеты из корня проекта:

```sh
cmake --preset editor
cmake --build --preset editor --parallel 2
ctest --preset editor
python3 tools/localization/update_catalog.py --check
```

Сохраните изменённые файлы перед сборкой: компилятор читает файлы с диска.
При обычных изменениях C++/QML пересобирать Docker-образ не нужно. QML встроен
в исполняемый файл, поэтому после изменения QML нужно пересобрать приложение.

## Переводы `.ts` — это XML

Файлы в `translations/` относятся к Qt Linguist. Расширение `.ts` здесь не
означает TypeScript. [.vscode/settings.json](../.vscode/settings.json) назначает
XML только файлам `.ts` внутри каталога переводов проекта.

При открытии такого файла в правом нижнем углу VS Code должен быть язык **XML**.
Если указан **TypeScript**, проверьте, что открыто рабочее пространство этого
репозитория, затем выполните **Developer: Reload Window**. Временный выбор
XML через индикатор языка помогает проверить причину; постоянное назначение
уже хранится в конфигурации проекта. Остальные `.ts` файлы других проектов
не нужно переназначать глобально.

Настоящие ошибки переводов проверяются командой **OpenQUI: Translations**.
XML-подсветка не заменяет проверку полноты языковых каталогов.
См. [ассоциации файлов VS Code](https://code.visualstudio.com/docs/languages/overview).

## Как читать Problems и вывод терминала

Цвет сообщения зависит от темы и от того, как инструмент пишет в stdout/stderr.
Красный текст сам по себе не устанавливает результат команды. Для сборки
проверяйте итог и код завершения, для тестов — итог CTest. Сразу после команды
в терминале можно выполнить `echo $?`: `0` означает успешное завершение этой
команды. После выполнения следующей команды проверяется уже её результат.

Панель **Problems** собирает сообщения разных источников. Смотрите источник
диагностики: C/C++ IntelliSense, TypeScript, компилятор и тесты проверяют разные
вещи. Пустая Problems не доказывает, что тесты прошли. Успешная сборка также не
доказывает работу физического устройства.

| Сообщение или симптом | Проверка и действие |
| --- | --- |
| `cannot open source file "QDir"`, `"QFileInfo"`, `"QObject"`, C/C++ 1696 | Проверьте подключение к Dev Container, установленное там C/C++ расширение и успешный Configure. Затем проверьте наличие базы компиляции. |
| C++ собирается, но IntelliSense показывает ошибки | Выберите `editor` в CMake Tools и выполните Configure. Используйте **C/C++: Log Diagnostics**, чтобы проверить фактический компилятор и пути. Если настройки верны, выполните **C/C++: Reset IntelliSense Database**. |
| Сотни TypeScript ошибок в `translations/*.ts` | У файла должен быть язык XML. Откройте правильное рабочее пространство и перезагрузите окно. |
| `cmake`, `c++` или `ninja`: `command not found` | Скорее всего, открыт терминал хоста. Откройте новый терминал после подключения к контейнеру и повторите проверку окружения. |
| `Could not find Qt6` / `Qt6Quick.pc` | Выполните проверку инструментов в текущем окружении. После изменений зависимостей пересоберите Dev Container. Для сборки на хосте нужны его development-пакеты. |
| `CMakeCache.txt` относится к другой папке, компилятору или Qt | Не используйте один каталог сборки для разных окружений. Следуйте разделу восстановления ниже. |
| В текущей папке нет `CMakePresets.json` | Откройте проект через workspace-файл и выполняйте команды из корня репозитория. |
| Docker не подключается или сообщает `permission denied` | Проверьте Docker на хосте командой `docker info`. Исправление прав/запуска Docker относится к настройке хоста; переустановка Qt в контейнере здесь не поможет. |
| CMake пишет `The qml plugin ... The plugin will not be linked` | Это предупреждение, а не сообщение C++ о недоступном заголовке. Сверьте результат настройки, сборки и GUI-тестов. Ошибка загрузки QML во время запуска требует отдельного исправления. |
| GCC пишет `error:`, Ninja останавливается, задача завершается с ошибкой | Это ошибка сборки. Начните с первого сообщения компилятора, исправьте его и запустите Build снова. Не отключайте анализатор для скрытия ошибки. |
| `ctest` показывает `Failed` или `Not Run` | Прочитайте вывод конкретного теста. `Not Run` может означать, что тестовый исполняемый файл ещё не собран; запускайте задачу Test, которая сначала собирает проект. |
| Окно приложения не появляется внутри контейнера | Окружение разработки использует offscreen-рендеринг для проверок. Обычный запуск на рабочем столе описан в getting-started; это не доказательство ошибки C++. |
| Не работают USB или звук реального устройства внутри контейнера | Dev Container не получает USB-устройства и аудиосессию хоста. Проверка оборудования выполняется отдельно на хосте. |

Для устранения ошибки полезны первая диагностика, команда, её итог и окружение.
Не начинайте с переустановки всех расширений или отключения TypeScript/C++:
сначала установите, какой источник выдал сообщение.

## Что делать после обновления проекта

| Что изменилось | Действие |
| --- | --- |
| C++ или QML | Сохранить файлы и выполнить Build |
| `CMakeLists.txt` или `CMakePresets.json` | Выполнить Configure, затем Build |
| Состав зависимостей или Dockerfile разработки | **Dev Containers: Rebuild Container**, затем Build |
| `.vscode/settings.json`, ассоциации языка или расширения | При необходимости **Developer: Reload Window**; проверить язык файла и расширения в контейнере |
| Только README/документация | Пересборка приложения не требуется |

Если база IntelliSense устарела, сначала повторите Configure. Если после смены
компилятора/Qt CMake сообщает о несовместимом кэше, сохраните старый каталог
сборки переименованием, например добавив к `build/editor` уникальный суффикс.
Убедитесь, что новое имя свободно, затем выполните Configure и Build.
Переименовывать нужно только каталог этой сборки; ресурсы, исходники и профили
устройств к нему не относятся. Для контейнерной и хостовой сборки выбирайте
разные каталоги.

## Почему гайд не нужно переписывать после каждого обновления

| Что задаёт актуальное поведение | Где хранится |
| --- | --- |
| Требования приложения к C++/Qt и состав целей | [CMakeLists.txt](../CMakeLists.txt) |
| Пресеты и каталоги сборки | [CMakePresets.json](../CMakePresets.json) |
| Зависимости окружения VS Code | [Dockerfile.dev](../packaging/Dockerfile.dev) |
| Запуск контейнера и настройка редактора | [.devcontainer/devcontainer.json](../.devcontainer/devcontainer.json) |
| Ассоциации файлов и CMake Tools | [.vscode/settings.json](../.vscode/settings.json) |
| Повторяемые команды Build/Test | [.vscode/tasks.json](../.vscode/tasks.json) |

Версии и зависимости обновляются в этих файлах. Гайд ссылается на их назначение
и на стабильные действия редактора, а не дублирует номера версий, путь домашней
папки, ID контейнера или число тестов. Его нужно менять при изменении самого
порядка работы или имён команд/пресетов; гарантировать неизменность любых
будущих интерфейсов VS Code невозможно.

Дополнительные инструкции: [сборка и запуск](getting-started.md),
[тестирование](testing.md), [разработка](development.md).
